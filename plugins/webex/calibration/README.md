# Judge calibration — grader pack

Not git-tracked. Working directory for the calibration exercise: the packs handed to graders,
and the sheets they hand back.

Method and reasoning live in `docs/judge-calibration-plan.md`. This file is the operating
procedure. Everything here except this README is regenerated by:

```
node plugins/webex/eval/score/build-calibration-pack.js <bundle-dir>...
```

## What you are being asked to do

We have two automated "judges" that rate the output of a task-extraction system. We need to know
how well their ratings agree with a person's. You are that person.

You will rate examples on a 1-4 scale. **Do not look at the model's rating before recording your
own** — it is withheld from your copy for exactly this reason.

## Two graders, separately

**Two people do this independently, each on their own copy of the pack.** The second grader is
not redundancy: two humans rating the same examples establishes the *ceiling*. If two people
agree with each other 80% of the time, a judge agreeing 78% is performing at human level. Without
that number, a judge-versus-human figure cannot be interpreted at all.

So each pack is duplicated per grader (`-marker-a.md`, `-marker-b.md`). The two copies are
identical apart from the title line. **Do not compare notes until both sheets are returned.**

## Two judges, graded in separate blocks

`task-fidelity` and `response-quality` are different judges with different prompts and different
rubrics. Agreement on one tells us nothing about the other.

**Finish one file entirely before starting the other.** Switching rubrics example-to-example
reliably produces grader error that looks like judge disagreement.

## What is in each pack

| File | Examples | Time |
|---|---|---|
| `task-fidelity-marker-<x>.md` | 24 extracted tasks | ~45 min |
| `response-quality-marker-<x>.md` | 16 replies | ~30 min |

Roughly a third of each set is genuine system output, a third was constructed to be wrong in
exactly one way, and a third was constructed to be reworded but still correct. **You are not
told which is which, and they are shuffled together rather than grouped.** A section heading
saying "perturbed to be wrong" would hand you the answer before you read the example, and the
constructed items still need human labels — the human-versus-human ceiling is computed over the
whole set, and a ceiling estimated from eight items would have a confidence interval too wide to
interpret the judge against.

The constructed third that is *still correct* is the one that usually gets skipped, and it is
precisely where the real bug lived: the judge once failed a correct extraction for "inventing"
wording that was verbatim in a message the harness never showed it. Without those cases,
calibration would have called the judge fine.

`ANSWER-KEY.md` records which is which. **It is not part of the grader's copy — do not send it.**

## Filling it in

Each file ends with a ratings table. Fill the `Rating` column with 1-4 and add a short reason.
Rate every row. Leave everything else alone.

If an example seems unratable, or you think the listed "facts a correct answer needs to convey"
are themselves wrong, say so in the reason column rather than guessing. That is useful signal
about our construction, not a distraction.

## On return

Per judge, separately: exact and adjacent agreement, the 4x4 matrix, mean difference, and a read
of every disagreement. Compute human-versus-human first — that is the ceiling — then each judge
against each human. Use quadratic weighted kappa: the scale is ordinal, and unweighted kappa
would treat a 4-vs-1 disagreement the same as 4-vs-3. Report raw agreement, the matrix and kappa
together; on a distribution clustered at 4 the kappa paradox can make a strong judge look weak.
